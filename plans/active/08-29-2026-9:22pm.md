# P0 — Public-site publication safety

## Finding

`config/public-sites/index.js` is **declarative**. Importing it does not deploy or upload a customer website.

The live mutation path is elsewhere:

```text
config/public-sites/index.js
        ↓ lookup only
backend/cms/public-site/site-manifest.js

explicit draft write
PUT /api/cms/site-shell/:part
        ↓
writeSiteShellDraft(...)
        ↓
components/.draft/*

explicit live promotion
POST /api/cms/site-shell/:part/publish
        ↓
publishSiteShellPart(...)
        ↓
ASSETS R2 published key
```

Agent Sam also has separate save-draft and publish-site-shell tools. That draft/publish split is worth keeping.

## Problems to close

1. `backend/cms/public-site/site-shell.js` still hardcodes `inneranimalmedia` / `iam` and duplicates shell-part configuration already represented by the public-site registry.
2. `shellBinding()` falls back across `CMS_BUCKET`, `ASSETS`, and `R2`; production publication should never guess which bucket to mutate.
3. Live publish currently copies draft bytes directly to a mutable production key without an expected-content/hash precondition.
4. Agent-driven publication is callable and must obey the same explicit production policy as the human CMS route.
5. Customer-site publishing needs an audit receipt: who published what site, from which draft hash, over which previous live hash.
6. Unrelated AgentSamRemix deploys must be mechanically incapable of publishing customer-site content.

## Target contract

```text
edit page/shell
    ↓
DRAFT ONLY
    ↓
preview
    ↓
explicit publish intent
    + authenticated actor
    + authorized workspace/site
    + exact configured storage binding
    + expected draft SHA-256
    ↓
hash live + draft
    ├─ identical → no-op receipt; zero R2 write
    └─ changed   → publish + receipt
```

Rules:

- `config/public-sites/*` describes sites; it never performs I/O.
- `backend/cms/public-site/` is the only public-site publication authority.
- Resolve shell parts/storage from the registry; remove site-name branching from `site-shell.js`.
- Production mutation uses the **exact configured binding**. No fallback bucket selection.
- Saving/editing is draft-only. No save endpoint or autosave may promote live bytes.
- Publish must be an explicit action. No GET, bootstrap, app deploy, route load, cron, or unrelated Worker deploy may publish customer content.
- Require the draft content hash/version being promoted. A stale publish fails instead of overwriting a newer draft.
- Hash live bytes before PUT; unchanged publication is a no-op.
- Record publication actor, site ID, workspace, new hash, previous hash, timestamp, and source action.
- `bin/agentsam deploy *` may deploy IAM application infrastructure but may not write the customer public-site `ASSETS` bucket.
- `bin/agentsam website *` is for `WEBSITE_ASSETS`, not customer public-site content.

## Proof / ratchet

Add focused tests/guards proving:

- unrelated Worker deploy → zero customer-site R2 mutations;
- unrelated frontend deploy → zero customer-site R2 mutations;
- draft save → live hash unchanged;
- identical explicit publish → zero payload write;
- stale draft hash → publish rejected;
- unauthorized workspace/site → publish rejected;
- no runtime code outside the public-site publisher may directly promote site-shell draft keys to published keys.

Do not remove the registry simply because it contains site-specific data. Remove mutation ambiguity around it.
