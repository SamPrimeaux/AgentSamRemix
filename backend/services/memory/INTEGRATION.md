# Memory service — factor-in handoff

Generated by `scripts/scaffold_memory_service.py`. Domain logic is in
`backend/services/memory/`. Do not smear Gemini/pgvector/Vectorize into
`app/`.

## Locked architecture

    frontend / API
         |
         v
    MemoryService          (remember/search/forget/update/get/list/consolidate)
         |
         +-- MemoryEmbedding --> GeminiEmbedding2Provider
         |
         +-- MemoryStore
                |
                +-- PostgresMemoryStore  --> agentsam.agentsam_memory_gemini2_1536
                |
                +-- VectorizeMemoryStore --> projection only; writes fail loud

Existing operational tables stay where they are:

- D1 `agentsam_memory` — control-plane SSOT for `agentsam_memory_save` / commit
- `agentsam.agentsam_memory` — structured operational facts (managed_pg projection)
- `agentsam.agentsam_memory_oai3large_1536` — OpenAI vector space; legacy only
- `agentsam.agentsam_memory_gemini2_1536` — Gemini semantic SSOT (this service)

Tools `agentsam_memory_save` and `agentsam_memory_search` route through commit/outbox
and `memory-service-bridge.js` — not direct table access from dashboard.

This service owns the missing Gemini pgvector twin. Vectorize
`agentsam-memory-gemini2-1536` may later be rebuilt from it.

## Public surface

Callers (Worker routes, tools) should look like:

    const memory = createMemoryService({ sql, env });
    await memory.remember({ content, workspaceId, subjectId, sourceType });
    await memory.search({ query, workspaceId, limit: 12 });

`index.js` does not export Gemini or Postgres classes.
